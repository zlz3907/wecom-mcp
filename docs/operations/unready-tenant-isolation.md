# 全量发现中的未就绪租户隔离

适用于 `--gnas-discovery-policy` 的动态发现及 hybrid 模式。GNAS 中合法存在的 Binding 不意味着其业务 Registry target、九表或 Z-S00 已初始化。过去任何动态租户的 Registry/Z-S00 发现错误都会使共享服务启动失败；此候选将该 Host 发布为固定不可用路由。

| 条件 | 行为 |
| --- | --- |
| 完整权威快照及公共配置有效，动态 Registry/Z-S00 已验证 | 构建/复用原服务与 OAuth 边界 |
| 完整权威快照及公共配置有效，动态 Registry/Z-S00 读取、身份或完整性验证失败 | 仅该权威 Host 所有路径返回 503、`Cache-Control: no-store`，不构建 MCP/OAuth 服务 |
| 未知、撤销或静态恢复模式未映射的 Host | 421；忽略转发 Host 作为租户选择依据 |
| 权威 resolver 失败、摘要错误、重复 Binding/Host/Source、非法公共配置、受保护 local mapping 漂移、存储冲突、handler 构建失败 | 保持全局失败关闭，启动拒绝或已有已知 Host 503 |

503 只输出固定 `MCP instance unavailable`，不返回上游错误、Registry 内容、租户标识或认证挑战。MCP、健康检查和 OAuth 元数据路径均不会进入其他租户的 handler。该状态不证明某种具体资产缺失，也不授予创建资产或修复权限。

保持原有已就绪 Binding 缓存规则：Binding 未变化时复用上次验证的实例名称和服务；本次候选不引入每次全量重读所有已就绪 Schema。Binding 身份变化、移除后重加会重新探测；未就绪结果不缓存，每次刷新重新只读探测，所以外部受控初始化完成后可以恢复。工具实际执行仍遵守既有读取和授权门禁。

对需探测的动态 Binding 分别使用上下文，最多并发 64 个（权威协议已有数量上限），每个探测预算最多 10 秒且不超过共享剩余预算的一半。探测失败只影响对应 Host；共享上下文本身取消/耗尽仍拒绝发布，以保留已有取消语义。保持已有 generation 原子替换和在途请求排空规则，因此 generation 变更的短暂共享排空窗口不变。

发现仅调用既有只读 Registry/Schema resolver，不创建九表、Z-S00、远程记录、成员权限、本地租户配置或状态文件。不就绪实例名称仅为配置验证占位，不参与可服务实例名称冲突判断；其身份隔离的状态路径仍接受公共存储检查。

验证使用 fake resolver、临时目录及 HTTP recorder，包括两租户正常/未就绪并存、重试恢复、身份变更、撤销、权威失联、重复路由/身份、全部未就绪、探测超时、静态恢复和既有 hybrid 能力。此候选未访问或切换生产，构建或本地验证不代表线上就绪。
